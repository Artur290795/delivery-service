Да, для **нашего проекта я бы тоже выбрал абстракцию обоих**. Но важно понимать, *почему именно здесь это оправдано*.

У нас получится:

```text
                 ExchangeRateService
                    /            \
                   /              \
              Cache            RateProvider
                ↑                   ↑
                │                   │
          RedisCache            CBRClient
```

А в тестах:

```text
                 ExchangeRateService
                    /            \
                   /              \
              FakeCache        FakeRateProvider
```

### Почему я согласен с твоим выбором

У нас уже есть **две разные внешние системы**:

* Redis — внешний storage/cache;
* ЦБ — внешний HTTP API.

Обе являются инфраструктурными деталями. Бизнес-логике `ExchangeRateService` на самом деле всё равно:

> «Откуда ты получил курс?»

и

> «Где ты его сохранил?»

Ему нужны только операции:

```text
получить значение из cache
сохранить значение в cache

получить курс
```

Поэтому абстракции хорошо отражают ответственность.

---

### Но есть важный момент

Я бы **не делал так**:

```python
class Cache(ABC):
    ...
    
class RedisCache(Cache):
    ...
```

и

```python
class RateProvider(ABC):
    ...
    
class CBRClient(RateProvider):
    ...
```

автоматически только потому, что «так положено по SOLID».

В Python нам вполне может хватить `Protocol`:

```python
class Cache(Protocol):
    ...
```

и

```python
class RateProvider(Protocol):
    ...
```

Тогда конкретные классы даже не обязаны явно наследоваться от этих Protocol.

---

### И теперь предлагаю тебе следующий шаг

Не будем пока писать весь `ExchangeRateService`.

Сначала спроектируем **контракты**.

Тебе нужно подумать, какие минимальные методы должны быть у:

```python
Cache
```

и

```python
RateProvider
```

Подсказка: посмотри на текущий код `ExchangeRateService`.

Сейчас он фактически делает четыре операции:

```text
Redis:
    ?
    ?

CBR:
    ?
```

**Попробуй сам написать два `Protocol` с минимальными методами.**
Не надо пока реализации `RedisCache` и `CBRClient`.

Я проверю твой вариант и, если где-то будет лишняя абстракция или неправильная сигнатура, разберём почему.
